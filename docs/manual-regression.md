# 人工回归清单

**改完审批 / 连接 / 渲染相关的东西，发版之前走一遍这里。**

这份清单存在的理由：0.7.2 到 0.7.5 四个修复版全部由人在手机上实测发现，
而当时自动化测试是全绿的。原因是那些故障落在**自动化摸不到的地方** ——
真实浏览器行为、真实 Kiro agent、真实网络。

自动化已经覆盖的不要重复测（见下方「已自动化」），这里只留**必须人来做**的。

## 每次都要走（约 5 分钟）

前置：`node scripts/release.js --install` 通过，并且**已经重载 Kiro 窗口**
（不重载跑的还是旧代码 —— 这一步漏过）。

- [ ] 执行「Kiro Bridge: 启动远程会话」，手机扫码或用已存的 URL 打开
- [ ] 触发一个需要审批的操作，手机上弹出授权框
- [ ] **在手机上点 `Allow`** → 卡片变成 `✓ 已允许 · Allow`，浮窗关闭
- [ ] 再触发一次，**在电脑上批准** → 手机浮窗**自动关闭**（不用手动刷新）
- [ ] 承接上一步，手机**退出重进 URL** → 那个框**不再弹回来**
- [ ] 再触发一次，先**返回会话列表再切回会话** → 框还在、按钮可点
- [ ] 手机**锁屏 3 分钟以上**再解锁，**停在原地不要操作** → 顶部「已断开，重连中」
      应自行恢复；恢复后不刷新，看内容能否继续更新
- [ ] 触发一个**没有永久授权**的工具 → 确认真的弹框
      （验证权限规则没被缓存。注意每测一次就消耗掉一个可用工具，见下方「注意」）

## 改到这些地方时额外走

**改了权限 / 授权范围**

- [ ] 点 `Always allow` → 检查 `~/.kiro/settings/permissions.yaml` 新增了对应条目
- [ ] 确认新增的是**工具名**级别的规则，范围符合预期
- [ ] 撤销：手工删掉那一行（**agent 改不了这个文件，只能你来**），
      重新触发确认又会弹框

**改了模型 / agent 配置**

- [ ] 在 `~/.kiro/logs/<最新时间戳>/kiro.log` 里搜 `modelId=`，
      确认实际请求用的是预期模型 —— 配置填错会**静默回落**到默认模型，
      问 agent 自己它答不出来

**改了 UI**

- [ ] 四种审批状态的配色都对：`⏸ 待确认`（琥珀）/ `✓ 已允许`（绿）/
      `✗ 已拒绝`（红）/ `⊘ 已取消`（灰）
- [ ] 会话列表的「待确认」徽标与卡片状态一致（两个观察者不能互相矛盾）

## 已自动化，不用手测

| 场景 | 在哪 |
|---|---|
| 授权链路记账、四个选项、scope、失败与重试 | `t12-approval.mjs` |
| 手机端浮窗队列、卡片状态、重连监听 | `t13-pending-ui.mjs` |
| 真断线重连后待批还在 / 电脑批准经 tail 推送 / 会话隔离 / 定向推送 / 桥重启清空 | `t14-e2e.mjs` |
| 会话列表的 waiting / running 判定 | `t9-live.mjs` |

## 注意

- **每测一次「未授权工具会弹框」就消耗掉一个可用工具**（点 `Always allow` 之后
  它再也不弹了）。测之前先想清楚用哪个，优先点 `Allow` 单次，把工具留给下次。
- **桥重启后按钮靠 Kiro 上游补发**，这条路需要真实 agent，自动化验不了。
  怀疑它坏了的话：重载窗口 → 手机重进会话 → 看之前挂着的授权有没有按钮。
- 清单里每一项都对应过一个真实故障。**发现新的失效路径就往这里加一行**，
  同时更新 `docs/approval-matrix.md`。
